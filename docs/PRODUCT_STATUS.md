# JumysAQ — отчёт: сделано / не сделано

Документ отражает состояние репозитория на момент составления. Используйте для питча, защиты и планирования доработок.

---

## 1. Сводная таблица

| Область | Статус | Комментарий |
|--------|--------|-------------|
| Единая лента вакансий + карточка | **Сделано** | `/jobs`, `/jobs/[id]`, фильтры |
| Регистрация / вход (email или телефон + пароль) | **Сделано** | JWT, localStorage на фронте |
| Профиль соискателя (навыки, район, опыт) | **Сделано** | `/profile` |
| Профиль работодателя + вакансии | **Сделано** | `/employer`, `/employer/new` |
| Отклики + статусы у работодателя | **Сделано** | `/employer/jobs/[id]/applications` |
| AI-матчинг + объяснения (Gemini / Groq fallback) | **Сделано** | `/api/match/for-me`, эмбеддинги + правила |
| AI анти-скам (score + причины) | **Сделано** | при создании/обновлении вакансии |
| Фильтры: сфера, район Актау, опыт, тип занятости | **Сделано** | в т.ч. студент / без опыта через `experience` |
| Флаг «verified» у работодателя | **Частично** | поле в БД и UI; нет процесса модерации / заявки |
| Верификация телефона / email (код SMS или письмо) | **Не сделано** | `phone_verified` выставляется упрощённо при регистрации |
| AI «улучшить текст вакансии» при вводе | **Не сделано** | отдельного эндпоинта и UI нет |
| Охват «сёла и районы области» как отдельный тип локации | **Частично** | город/район в модели; сид в основном под Актау |
| Telegram: подписки + уведомления о вакансиях | **Сделано** | бот + API подписок |
| Telegram: полный отклик / приглашение без сайта | **Частично** | уведомления есть; сценарий отклика из бота ограничен |
| Мобильная адаптация UI | **На усмотрение** | зависит от текущих правок в `globals.css` / layout; проверять вручную |
| Админка / ручная верификация работодателей | **Не сделано** | за рамками MVP в питче |

## 2. Backend (FastAPI)

**Реализовано:** `auth`, `users` (профили seeker/employer), `jobs` (CRUD, список с фильтрами, risk+embedding), `applications`, `match`, `telegram` (subscribe), health, CORS, `PUBLIC_APP_URL` для ссылок в уведомлениях.

**Не реализовано:** отправка OTP (SMS/email), эндпоинт «подтвердить код», webhook админки для `verified`, опционально — `POST /api/jobs/draft-improve` для LLM-редактуры текста.

---

## 3. Frontend (Next.js)

**Реализовано:** основные страницы приложения, API-клиент, типы, карточки вакансий, матч, формы.

**Проверить отдельно:** адаптив (viewport, `container-page`, кнопки, таблицы на узких экранах), блок «новости / скоро вакансии» — если добавлялись локально, зафиксировать в этом файле.

---

## 4. Telegram-бот

**Реализовано:** команды, подписка, выдача вакансий, связь с API.

**Усиление под продуктовое описание:** deep-link на отклик, кнопки «открыть на сайте» уже через `PUBLIC_APP_URL` на стороне API для пушей о вакансиях.

В корневом README в «Решении» указаны формулировки в идеальном виде (например, подтверждение телефона, AI дотягивает текст). ## 6. Промпт для реализации недостающего

Ниже готовый текст для другого агента / разработчика. Вставьте репозиторий и контекст путей.

```
Ты работаешь в монорепозитории JumysAQ (hackaton): backend/ FastAPI, frontend/ Next.js 14 App Router, bot/ aiogram.

Цель: закрыть пробелы между docs/PRODUCT_STATUS.md и продуктовым видением, не ломая существующий MVP.

Сделай по приоритету:

1) Верификация телефона (MVP-уровень)
   - Добавь таблицу или поля для OTP: код, срок действия, попытки (или in-memory/redis — на усмотрение, для хакатона допустим in-memory с TTL).
   - Эндпоинты: POST /api/auth/request-phone-code { phone }, POST /api/auth/verify-phone { phone, code } — после успеха выставлять user.phone_verified = True.
   - Для продакшена оставь заглушку провайдера SMS (интерфейс + mock), чтобы без ключа сервис поднимался.
   - Обнови frontend: экран/шаг после регистрации или в профиле «Подтвердить телефон».

2) AI «улучшить описание вакансии»
   - POST /api/jobs/improve-description { title, description?, industry? } → { improved_description } через существующий слой app/services/ai.py (Gemini приоритет).
   - На frontend в /employer/new кнопка «Улучшить текст (AI)» с индикатором загрузки и возможностью откатить.

3) Локации: сёла / район области
   - Минимум: расширь константы района/города на фронте (AKTAU_DISTRICTS или отдельный список «Населённые пункты Мангистау») и фильтр в /api/jobs если нужно поле settlement_type (optional enum: city | village).
   - Сид: 2–3 демо-вакансии с village, чтобы на защите было видно.

4) Telegram: ближе к «без сайта»
   - В боте: после /jobs добавь inline-кнопку «Откликнуться» → deep link на сайт /jobs/{id} с токеном или просто открытие вакансии + текст «войдите и откликнитесь»; либо mini-flow: запрос cover_letter в чате и POST /api/applications с user, привязанным по telegram_id (если уже есть связка пользователя с telegram_id в API — используй; если нет — только ссылка на сайт).

5) Мобильная вёрстка
   - Пройдись по app/layout.tsx, globals.css, основным страницам: safe-area, min touch targets 44px, перенос фильтров jobs в drawer на sm, без горизонтального скролла.

Ограничения:
- Не удаляй существующие эндпоинты без миграции фронта.
- Сохрани стиль кода и именование.
- После изменений: npm run build в frontend, импорт app.main в backend, кратко обнови docs/PRODUCT_STATUS.md таблицу.

Начни с чтения backend/app/models.py, routers/auth.py, routers/jobs.py, frontend/lib/api.ts, frontend/app/employer/new/page.tsx.
```
